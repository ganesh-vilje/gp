## Known open issue — read before starting M2

**B-001** (open, tracked in `.ai/project-state/blockers.md`): an intermittent session-resolution race
in `app/middleware/session_loader.py` causes a spurious 401/403 on a request immediately following a
fresh login, roughly 1 in 5-20 requests. First found locally at T-009; **hit real CI 5 separate times**
across T-016 and T-017's PR runs (always a different, otherwise-passing test; always clears on a
rerun). This is not caused by any M1 task's own code — it reproduces with plain login+logout alone —
but it now measurably reduces CI signal quality: every PR has a nontrivial chance of a red run for a
reason unrelated to that PR. **Recommend fixing this before starting M2 feature work**, not after.

## How to run this yourself

```
# Terminal 1 — API
cd api
$env:ENVIRONMENT="dev"
$env:DATABASE_URL="postgresql+psycopg://panchayat:panchayat@localhost:5432/panchayat"
$env:SECRET_KEY="<32+ char value>"
$env:USERNAME_HASH_SALT="<different 32+ char value>"
$env:ALLOWED_ORIGINS="http://localhost:3000"
$env:ALLOWED_HOSTS="localhost,127.0.0.1"
uv run bootstrap-admin          # creates the first admin account, one time
uv run uvicorn app.main:app --port 8000 --no-proxy-headers

# Terminal 2 — web
cd web
$env:NEXT_PUBLIC_API_BASE_URL="http://localhost:8000"
npm run dev

# Browser
http://localhost:3000/login     # log in with the bootstrap-admin credentials
http://localhost:3000/complaints  # log a complaint, note the number
http://localhost:3000/          # (new tab/profile) look up that number
```
